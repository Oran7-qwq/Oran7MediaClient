# 视频空间改版方案

## 1. 设计方向

采用「一个最近播放入口 + 一个媒体库」的浏览页，以及以画面为中心的播放页。用户进入视频空间时可以选择内容，开始播放后切换到播放布局。

首版视觉沿用音乐列表已经建立的简约工业风。用有遮挡能力的半透明底面、少量强调色刻线和清晰的文字层级，配合影片缩略图丰富画面。

本文是设计与实施计划。V0 已实施，文中的历史记录、缩略图媒体库和收藏能力分别在后续阶段接入。

## 2. 当前基线

| 现有内容 | 源码入口 | 改版中的用途 |
|---|---|---|
| 视频页、文件打开、直播房间输入 | `src/qml/RightPage/MainStackView/VideoPlayerStack.qml` | 保留页面路由，组织浏览态与播放态 |
| 渲染项、信息面板、弹幕覆盖层 | `src/qml/Components/Oran7GlobalComponents/Oran7VideoRendererItem.qml` | 复用视频渲染、宿主挂载与来源信息 |
| 播放命令及只读播放快照 | `src/cpp/Oran7MediaClient/Oran7MediaClient.h` | 沿用 Client 与 Client.playback |
| 直播地址解析、B站登录入口 | VideoPlayerStack 内的相关对象与回调 | 接入房间卡和播放设置 |
| 弹幕开关、连接状态、普通弹幕与醒目留言 | VideoPlayerStack、BilibiliDanmakuClient | 接入播放态弹幕菜单与状态提示 |

当前页面的主要结构是铺满的渲染区域和右侧收折菜单，浏览内容的模型与持久化需要补充。现有暂停入口存在通过 `Client.playVideo(source)` 切换状态的调用，迁移前需要核对语义，统一接到明确的播放控制命令。视频专用全屏操作在本方案中作为新增交互，实施时接入主窗口的全屏与普通几何恢复机制。

主窗口默认尺寸为 990 × 564，左侧导航默认宽度为 204。布局依据视频页实际可用宽高计算。

### 3.1 顶部工具区

- 左侧使用「视频空间」主标题，空间充足时显示低对比度英文装饰文字。
- 右侧为搜索与「＋ 导入」，菜单包含打开本地文件、添加直播房间。
- 搜索只过滤当前页签中的名称、文件名或房间号。空输入立即恢复内容。
- 搜索宽度随可用空间变化，窄时收成可展开入口，保留清空和退出操作。

### 3.2 最近播放横幅

- 全页只显示一个最近播放入口。左侧为上次缩略图，右侧为标题、观看进度和继续按钮。
- 图片向信息区渐隐，正文所在区域始终有足够底色。
- 标准高度约 152 px。页面高度低于 520 px 时收至约 112 px，优先展示标题、进度与按钮。
- 没有历史时显示「打开一段视频」和导入入口。文件失效时展示定位文件操作。
- 已看完的内容显示「重新播放」，从头开始。直播历史显示「进入直播间」，重新解析地址。
- 用户搜索时收起横幅，使搜索结果尽快进入视野。

### 3.3 页签与工具行

「本地视频」「直播房间」「收藏」共用一个内容区域。页签下方仅保留选中强调线，右侧放排序及网格／列表切换。

默认选中本地视频。页签各自保留搜索词、滚动位置和排序。返回浏览页时恢复先前上下文。

### 3.4 本地视频卡片

- 16∶9 缩略图作为主要视觉，保留 8～10 px 圆角。
- 时长显示在缩略图右下角的小底板上，观看进度使用底部细条。
- 图片下方为单行标题和一行辅助信息，超长标题省略并可悬停查看。
- 辅助信息优先显示观看进度，其次为添加时间。完整路径与技术参数放入详情。
- 悬停时轻微抬亮底面，显示播放和更多入口。阴影和位移保持克制。
- 点击卡片直接播放。更多菜单提供收藏、定位文件、从媒体库移除。
- 移除条目只修改媒体库记录。失效文件保留可识别的卡片和重新定位入口。

### 3.5 直播房间卡片

沿用本地卡片的尺寸与间距，内容换为封面、房间名、主播名、房间号和状态。状态明确区分直播中、未开播、正在检查与未知。

房间封面或状态尚未取得时使用占位。直播中可用小型状态点，动画遵守项目总开关。

点击房间后即时解析真实房间号与可用地址。失败反馈留在当前房间，提供重试。登录、刷新直播流和弹幕操作归入播放态的直播菜单。

### 3.6 收藏与列表视图

收藏支持本地视频和直播房间，卡片带简短来源标记。名称、封面和状态沿用原条目。

列表模式用于大量文件。行内展示小缩略图、标题、进度或直播状态、时长与更多菜单。宽度不足时依次隐藏添加时间和辅助信息，标题与播放入口始终保留。

### 3.7 空态与失败态

| 状态 | 展示及操作 |
|---|---|
| 本地库为空 | 简洁图形、导入说明、打开文件按钮 |
| 没有直播房间 | 添加房间入口与输入示例 |
| 没有收藏 | 说明卡片更多菜单中的收藏入口 |
| 搜索无结果 | 当前关键词、清空搜索 |
| 缩略图失败 | 统一占位封面，文件仍可尝试播放 |
| 文件失效 | 标记路径失效，支持定位或移除记录 |
| 直播状态请求失败 | 显示未知，保留重试 |

## 4. 播放态

```text
┌──────────────────────────────────────────────────────────┐
│ ‹ 视频库     老电影.mp4                        详情   ⋯   │
│                                                          │
│                                                          │
│                       视频画面                           │
│                                                          │
│                                                          │
│          ─────────────●───────────────────────            │
│ ▶   12:34 / 1:48:20              音量   倍速   全屏       │
└──────────────────────────────────────────────────────────┘
```

### 4.1 操作规则

- 开始播放后，上下浮动控制区覆盖画面。画面按比例适配，控制区显隐不改变渲染项尺寸。
- 播放控制栏保留原有透明背景、白色播放图标、Oran7ProgressSlider 与悬停音量弹窗。
- 鼠标静止约 1.5 秒后淡出控制栏与标题栏，两者完成淡出后再等待 2 秒隐藏鼠标。累计移动达到 2 px 时恢复显示。菜单展开、拖动进度或音量、媒体准备和错误展示期间保持可见。
- 单击画面切换控制区显隐，双击进入或退出全屏。播放／暂停使用明确按钮或空格。
- 退出全屏和关闭菜单由 ESC 从内向外处理。输入框聚焦时不触发播放快捷键。
- 本地视频展示进度、时间、音量、可用的倍速与全屏操作。倍速入口以现有内核能力核实结果为准。
- 直播展示直播状态、音量、刷新流、弹幕和全屏操作。只有后端明确支持回看时才展示时间轴。
- 视频详情和弹幕设置从右侧按需打开，窄窗口中使用覆盖式面板。

### 4.2 浏览与播放的关系

「返回视频库」切回同页的浏览布局，当前播放继续运行。顶部用紧凑的正在播放入口返回画面，复用同一个播放器和渲染项。

切换应用左侧导航仍沿用现有页面离开时的播放策略。实现时区分同页布局切换与 StackView 页面失活，避免返回视频库误触发离页暂停。

选择新内容时切换至播放态并显示准备状态。首帧到达后展示画面，失败时保留重试和返回视频库。暂停状态不能被 UI 淡入淡出覆盖。

## 5. 尺寸与视觉规范

### 5.1 布局

| 页面可用宽度 W | 网格列数 |
|---|---|
| W < 480 px | 1 列 |
| 480 ≤ W < 760 px | 2 列 |
| 760 ≤ W < 1040 px | 3 列 |
| W ≥ 1040 px | 4 列 |

初始外边距 20 px，窄页缩至 16 px。卡片横向间距 14 px，纵向间距 18 px。列数变化时保持当前条目附近的滚动位置。

顶部操作和页签保持可访问。最近播放横幅与卡片随一个纵向滚动区域滚动，避免多个横向卡片栏占满页面。实际实现可通过一个带头部区域的虚拟化视图组织内容。

### 5.2 颜色与字体

- 页面基础面使用深色半透明底面，文字区提高遮挡程度。背景图主要从留白和卡片间隙透出。
- 主文字采用接近白色的中性色，辅助文字使用低一级亮度。强调色用于页签、进度和关键按钮。
- 缩略图周围只保留少量短刻线或编号，卡片信息以实际内容为主。
- 页面标题约 22 px，卡片标题约 14 px，辅助信息约 12 px。接入字体偏好并验证中英文长度。
- 页面提供自身的 surfaceColor、textColor、secondaryTextColor、accentColor 等样式参数，由主界面显式传入。
- 下拉设置的 Oran7MainUiSetting 样式继续由设置界面使用。视频页优先沿用主界面已有主题语义。

### 5.3 动效

页签选中标记约 180 ms，卡片悬停约 140 ms，浏览／播放布局切换约 180～220 ms。控制区通过透明度和轻微位移过渡，视图容器保持稳定。

影片卡片和详情面板的加载过程使用固定尺寸占位。大量卡片同时出现时优先显示静态内容，滚动期间避免逐项播放入场动画。

## 6. 数据与运行约定

### 6.1 数据来源

媒体库需要持有稳定条目 ID、来源类型、标题、本地路径或房间 ID、封面缓存引用、收藏标记及时间字段。历史记录另外保存最近打开时间、有效播放位置与已看完状态。

本地路径通过统一的 Windows 路径规范化规则去重。直播条目以解析后的真实房间 ID 归一，用户输入的短号可保留为展示信息。收藏引用同一条目 ID。

持久化保存房间身份。播放时重新取得直播地址，临时签名地址、登录凭据和响应正文继续遵守既有凭据与日志约定。

### 6.2 观看进度

- 只在当前来源属于本地视频且后端位置有效时更新历史。
- 播放中约每 5 秒合并一次持久化，暂停、切换媒体和退出前补采集。
- 读取位置时关联当前请求代际，播放器停止后的归零通知不得覆盖上一条历史。
- 播放结束事件标记已看完。首版可将距离曲尾不足 10 秒且已看过至少 90% 的条目视为重新播放候选。
- 继续播放须等待播放器准备完成和时长有效后，按该次请求只提交一次 seek。用户主动拖动进度后撤销待执行的恢复意图。

### 6.3 异步与缓存

缩略图提取与媒体信息读取进入后台有界队列，优先处理可见卡片，初始最多两个任务并发。缓存键包含规范路径、文件大小和修改时间，文件变化后重新生成。

缩略图使用磁盘缓存配合有界内存缓存，首版磁盘预算建议 256 MiB。查询结果按条目 ID 与代际回到模型，过期任务结果不能覆盖新文件。

直播状态首版按进入页签或手动刷新时获取，同房间合并请求并限制并发。后台页停止周期刷新，列表状态检查与实际播放解析分别管理。

### 6.4 所有权

新增业务由 Client 持有的视频库服务管理，候选类名为 Oran7VideoLibraryService。条目用 QAbstractListModel 暴露，候选类名为 Oran7VideoLibraryModel。按阶段实际职责决定是否拆分更多类。

服务采用 unique_ptr 独占，QML 借用 CppOwnership。QObject 和模型只在 GUI 线程更新，后台任务捕获值快照与取消控制。正在播放状态继续以 Client.playback 为权威。

媒体库记录通过 AppConfig 的既有原子保存入口提交。缓存文件留在应用缓存目录。实施时补充配置结构与版本迁移，并保留旧配置的未知字段。

## 7. 页面组织建议

保留 VideoPlayerStack.qml 作为现有路由入口，按实际职责逐步拆出以下组件。

| 建议组件 | 职责 |
|---|---|
| Oran7VideoLibraryPage | 浏览布局、页签、搜索与排序 |
| Oran7VideoResumeBanner | 最近播放及空态横幅 |
| Oran7VideoLibraryCard | 本地、直播与收藏卡片 |

## 8. 实施阶段

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| V0 布局与播放入口 | 浏览／播放两态、顶部导入、房间输入、单个最近入口占位、统一播放控制布局 | 现有本地与直播可打开，弹幕与全屏可操作，默认尺寸布局完整 |
| V1 本地媒体库 | 导入模型、文件卡片、异步缩略图、网格／列表、搜索排序、失效文件处理 | 大量条目滚动流畅，重复导入归一，切页不阻塞 GUI |
| V2 历史与收藏 | 观看记录、继续播放、最近横幅、收藏页签、持久化与迁移 | 重启可恢复，快速切换不会串进度，停止归零不会清空历史 |

## 9. 验收清单

- 默认 990 × 564、导航展开／收起、最大化以及 125%／150% DPI 下验证操作可达。
- 缩窄页面后列数正确，标题和菜单不重叠，页签与滚动位置能恢复。
- 浏览与播放反复切换期间，画面宿主、播放状态和进度保持一致。
- 窗口最大化、全屏退出、菜单 ESC 和输入框快捷键互不冲突。
- 直播继续支持真实房间 ID 解析、登录、地址刷新、弹幕与醒目留言。
- 媒体准备失败、文件失效、缩略图失败及网络失败均有明确反馈。
- 缩略图任务、网络请求和历史恢复按代际过滤，后台工作不阻塞 GUI。
- 主页面样式通过自身参数控制，中英语言及字体设置下可正常排版。

实施阶段使用隔离检查验证模型、持久化、恢复逻辑和关键 QML 交互，只构建 Release。主程序真实播放、硬件渲染、直播账号及最终视觉效果由用户运行验收。

## 10. V0 实施记录

2026-11-11 完成浏览态与播放态切换，新增 Oran7VideoLibraryPage、Oran7VideoPlaybackToolbar 并接入 qml.qrc。浏览页提供当前会话横幅、本地文件选择／路径输入、直播房间输入与登录入口。媒体库模型接入前，使用真实入口和引导空态。

播放态复用原有渲染组件与弹幕层，新增明确的 Client.togglePlayback 命令，接入进度、音量、详情设置、直播刷新与全屏。全屏把同一播放表面移到主窗口内容层上方，退出时恢复原先的普通／最大化状态。

直播解析按每次请求创建独立对象，替换或离页时取消旧请求。地址回调绑定 QObject 上下文，网络请求有超时，先通过 room_init 归一真实房间号。正在播放来源变化会撤销未完成的旧直播意图。

## 12. 本地视频缩略图与缓存

2026-11-11 接入 Oran7VideoThumbnailCache。观看记录新增只读 thumbnail role，缩略图 URL 为运行期缓存信息，配置继续只保存观看记录身份。历史中的本地记录显示 16∶9 真实画面，最近观看横幅复用同一张图。

任务经 Oran7Async 后台队列串行提帧，每次请求只携带文件路径、缓存目录和共享取消标记。使用应用自带 ffmpeg.exe 在约 2 秒处取帧，短视频回退首帧，以 320×180 JPEG 原子写入应用 CacheLocation/video-thumbnails。输入协议限制为本地文件和管道，解码进程有超时，退出时协作取消正在执行的提帧任务。

缓存键包含版本、规范路径、文件大小和修改时间。缓存命中后直接读取图片，源文件变化时生成新条目，损坏图片重新提取。目录预算为 256 MiB，超出预算时优先清理较旧条目。提取失败保持占位，观看记录仍可操作。

隔离检查通过合成短视频验证真实像素、短片回退、重建缓存实例后免提取复用、损坏缓存恢复、文件修改失效和删除后的占位结果。此阶段服务于已有本地观看记录，直播封面仍按直播信息补全阶段接入。

HDR 封面补充：提帧前用同目录的 ffprobe.exe 探测首个非封面视频流的色彩信息。PQ/HLG 源先输出 RGB48 高精度像素，在后台按播放渲染器的 SDR 策略执行传递函数、BT.2020→BT.709 线性色域转换、亮度映射和色域压缩，最后编码 sRGB JPEG；不再将 PQ/HLG 编码值直接量化为普通 RGB。流级峰值元数据不可用时回退 1000 nit。现有 FFmpeg 不含 zscale，因此没有增加该滤镜依赖。探测失败显示占位，不能持久化颜色未知的错误封面。

缓存算法版本升级为 v2-hdr-srgb，已有 v1 封面下次请求自动重新提取，无需修改原视频或手动清缓存。解码仍在独立辅助进程、串行后台队列中，探测与提帧分别限时 5 秒并响应退出取消。离线检查覆盖 PQ/HLG 高位深色块、真实像素色彩、旧缓存换代、损坏恢复与磁盘复用；额外用用户提供的 4K PQ 视频只读验证提帧。

## 14. 直播房间资料

2026-11-11 接入内部服务 Oran7LiveRoomInfoService。直播记录展示房间标题、主播名、封面、头像与开播状态，进入直播页签时异步查询，单条记录支持手动刷新。使用房间 get_info 与主播 get_anchor_in_room 公开资料接口，先取得真实房间号，再查询对应主播。

名称、封面和头像 URL 随 video.history 保存，重启可复用展示信息。封面与头像由 QML Image 加载并使用内存缓存。开播状态在重新查询成功前展示未知／查询中，失败保留已缓存内容。成功查询节流 120 秒，失败节流 30 秒，手动刷新可绕过节流，同一房间合并查询，最多两个房间并发。

服务异步使用 QNetworkAccessManager，每步请求带超时，退出取消在途请求。资料回调按原房间身份匹配历史行，已删除的记录不会被迟到结果恢复。打开直播仍由原播放入口即时解析流地址。隔离替身检查覆盖资料补全、重建模型、去重、节流、失败回退、并发上限与迟到结果。
