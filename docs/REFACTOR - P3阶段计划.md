## 2. P3-1 启动协调与首次显示

### 目标与所有权

先给出可响应的轻量加载反馈，再展示已应用初始配置且布局可用的主窗口。不能只添加一段动画而继续暴露默认主题、默认尺寸或未挂载布局。

- Oran7StartupCoordinator 由入口持有，是普通 QObject，不新增全局单例、不放回 Client；统一拥有启动阶段、就绪条件、错误及交接状态。
- Oran7StartupWindow.qml 使用内嵌静态资源和简单动画，显示真实阶段，如读取配置、加载界面、准备显示；不展示虚构百分比、不设置固定等待秒数。
- 沿用同一 QQmlApplicationEngine，QML 只显示状态和提交操作意图。新增 QML 手工加入 qml.qrc。
- 明确主窗口对象的定位，消除“第一个根对象必定是主窗口”的假设，防止把窗口配置应用给启动窗口。

### 实施边界

1. 先记录启动反馈首帧、主 QML 创建、配置应用、布局就绪和主窗口首帧的时点，确认闪烁来源。保留现有字体、语言、主题和配置默认值契约。
2. 拆开配置读取与窗口应用时序，首屏所需的主题、字号、窗口尺寸/位置/状态在正式显示前落地；不重复读取全局配置。
3. 评估 QQmlComponent 异步加载/孵化与分阶段创建。QObject/QQuickItem 和窗口操作仍在 GUI 线程，不用 sleep、循环 processEvents 或同步等待推动动画。
4. 就绪至少汇总根对象创建、初始页面可用、配置应用、必要布局和有效首帧；Component.onCompleted 或单次 callLater 不能单独作为完成条件。
5. 隐藏主窗可能不产生有效首帧，必要时以完整启动覆盖层保护曝光，再确认首帧并交接。重复就绪只执行一次交接。
6. 不等待全量曲库扫描、在线歌单、网络连通或抓屏首帧；这些任务继续后台加载。所选背景在遮罩内预热，视频等待真实有效首帧，失败/5 秒超时固定回退图片/主题底色。
7. 创建失败、就绪超时及用户提前退出都有明确结束路径；失效迟到回调，不能永久转圈、留下启动窗口或重复显示主窗。

### 验收

- 离线检查：阶段推进、重复/迟到通知、就绪条件不全、失败/超时/取消，以及配置目标窗口的定位；检查资源和实际 QML 创建。
- 用户运行：冷/热启动、普通/最大化窗口、不同 DPI/多显示器、深浅主题、背景视频开关、大曲库和断网；确认无明显首屏闪烁、几何跳变或焦点异常。
- 记录真实启动阶段耗时，不把离屏检查当成 DWM/透明窗口曝光效果的验收。

## 3. P3-2 预览生命周期异步化

### 目标与状态

普通启停、应用抓屏设置、自动恢复和设备变化不在 GUI 线程等待 worker 结束。保留退出时的受控 join 作为安全收尾，不能用强杀线程替代资源回收。

由现有控制器或其独占的非单例会话对象维护唯一预览状态，例如 Idle → Starting → Running → Stopping → Idle，并包括 Recovering/Error；状态名称在实施时统一。previewBusy 等属性从状态派生，QML 与 Bridge 不再各存一套运行/等待标记。

录制状态继续归 Oran7RecordingSession，不合并预览与录制状态机。Preparing/Recording/Stopping 期间仍拒绝破坏采集资源的设置修改。

### 实施边界

1. 将 stop 请求与完成拆开：GUI 发出取消后立即返回，后台退出及线程 finished 到达后再销毁会话/worker、启动下一会话或回滚。核对现有直接 stop 调用者，避免它们继续假定“返回即已停止”。
2. 每轮启动、重启、恢复及参数应用都有请求代际；旧 worker 的 started/stopped/error/finished/首帧回调不能结束或覆盖新请求。
3. 连续自动保存只保留最新待应用意图，保持有界；不能同时起多个 worker，也不能让旧请求失败后把新参数回滚掉。所有已接受请求都需完成、失败或被替代的明确终态，QML 不得一直显示待保存/应用中。
4. 继续保留现有 Client.screenCapture、applyCaptureSettings 返回 ok/pending/msg 和应用结果信号的兼容语义；如需新增关联信息，先核对工作台与 Bridge 的调用点。
5. 区分目标参数、正在应用的参数与最后确认可用参数，明确配置提交/失败回滚的时机。记录图创建成功、首帧和实际应用完成的不同含义，不能把仅创建成功误报为已恢复画面。
6. 参数校验继续保证采集 FPS 不低于录制 FPS，录制忙状态限制不变；落盘经现有配置管理器，只改最新快照的 capture 分组。
7. 保留显示器 GDI 身份追踪、拓扑重映射、有限重试和显式重连入口，超时后给出可恢复错误。恢复预算在真实产帧后重置，不以错误重建循环假装恢复成功。
8. worker 只持配置值、共享录制 Feed 和安全帧提交回调。停止完成之前不能释放仍被 worker 使用的设备、邮箱、纹理或渲染依赖。
9. 同步的图创建/驱动调用可能不能即时取消，需如实维持停止中状态；不承诺驱动调用可强制中断，不用无限等待共享锁。

### 验收

- 扩展现有 capture-recovery/capture-bridge/recording 检查，覆盖快速启停、应用中再次提交、旧失败晚到、停止中显示变化、回滚失败、设备丢失、有限恢复及退出。
- 用可控的慢 worker 验证 GUI 事件仍推进，且旧会话结束前不会启动新会话；区分普通交互路径与最终析构 join。
- 保持 P2-7 render-sync 检查通过，确认取消/覆盖释放槽位租约，预览忙槽不影响录制原始帧处理。
- 用户运行：连续切显示器/分辨率/FPS、停止后重连、录制忙时尝试改参数、恢复中退出，观察 UI 响应及资源回收。

### 实施记录（2026-10-27）

- Oran7ScreenCaptureController 是唯一预览状态权威：Idle / Starting / Running / Stopping / Recovering / Error；previewBusy/previewError 只读。启动意图独立于实际状态，开始/停止/重连均为提交请求。
- 控制器 unique_ptr 持有 QThread，不再借用或跨线程访问 worker QObject；GUI/worker 只共享 Oran7CaptureControl 的原子取消/日志意图及 RecordingFeed。停止关闭 Feed、置取消并 quit，不做阻塞 join。
- worker finished 后仍可能执行延迟删除或 TLS 清理；GUI 用 wait(0) 零超时探测，未完成则 10ms 定时器再次检查。资源句柄保持到原生线程完全结束，不重叠启动多个 worker。唯一阻塞 wait 在显式 shutdown，Bridge 退出使用该入口，早于 RenderBridge/设备释放。
- 区分最新待应用目标、在途快照、已保存配置与最近首帧验证的可用目标。新参数只在当前代际首帧成功后保存；图 started 不代表应用成功。未绑定界面时仅保存，日志热更新不重启。
- applyCaptureSettings 兼容 ok/pending/msg 并追加 requestId；只保留一个最新请求。captureRequestFinished 返回 requestId/ok/msg/superseded，取消/替代/失败/成功都有终态。旧无编号信号仅为最新异步请求兼容转发；同步返回本身就是终态。
- 恢复保留 GDI 身份/稀疏原始索引重映射、300ms 间隔和最多 8 次重建，预算只在实际首帧后清零。默认首帧超时 5 秒；参数请求超时会失败并恢复旧配置，回滚失败进入 Error。驱动不可即时中断时保持 Stopping，报告等待原因，直到它真正返回才重建；不强杀、不假装已停止。
- 保存只更新最新配置快照的 capture 分组；失败恢复自己的分组，新参数失败不写入磁盘。录制准备/运行/收尾继续拒绝破坏采集资源的操作；预览忙时禁止开始录制和保存输出，采集 FPS ≥ 录制 FPS 约束保持。
- 工作台直接绑定后端 previewBusy/previewError；请求编号过滤迟到通知，应用结果不覆盖期间的新草稿；底部显示启动/停止/恢复提示。新增 14 条中英文文案经显式 oran7_update_translations 维护。
- 验证：Release 构建通过，完整 CTest **31/31** 通过（80.68 秒），最终 capture-recovery/capture-bridge/render-sync 定向复验通过；恢复夹具共 116 项断言，覆盖慢驱动、慢析构、首帧超时、连续提交/晚到错误、停止中再启动、磁盘失败/回滚失败、渲染项销毁和退出。真实 QML 夹具增加请求关联与草稿保护检查。记录见 build/refactor-work/P3-2/result.md。
- 边界：现有同步 monitors 枚举/校验接口仍保留；本阶段消除普通预览生命周期中的阻塞线程等待，不宣称所有驱动调用均已移出 GUI。未启动主程序或真实采集；真实切屏/分辨率、持续录制与驱动行为待用户验收。

## 4. P3-3 采集职责与资源拆分

### 目标与候选对象

用户指定先实施本项，因此沿用现有控制器的启停、代际和同步收尾契约，先分离线程与资源职责；P3-2 后续在这个边界上异步化。结构提取与转换算法、画质参数或编码行为变化分批交付。

- Oran7DesktopCaptureWorker：承接 DdaGrabWorker 的图建立、抓取循环、停止检查和抓屏错误输出，属于采集线程。
- Oran7CaptureFrameConverter：承接当前 worker 内预览色彩转换、录制转换/缩放及读回资源。实施时根据设备/上下文归属决定是否分为两个普通对象，不强制为每个函数创建类。
- 控制器/预览会话：保留 GUI 请求协调、参数应用/回滚、恢复和状态发布；不直接执行转换或持有复制的运行状态。

新增/拆分类型使用 Oran7 前缀，放在 Oran7ScreenCapture 模块，不放 GlobalSingleton。普通转换器可由 unique_ptr 独占；QObject worker 在 GUI 构造不持 GPU 资源的空壳，moveToThread 后才建立图、设备与转换器；线程 finished → deleteLater 在采集线程销毁。控制器以 QPointer 借用，禁止 GUI 直接 delete 后台 worker，禁止 unique_ptr 与 QObject parent 双重拥有同一对象。

### 必须保留

- 不重写 Oran7RecordingSession/Backend、编码器、封装器或播放器内核。
- 保留 BGRA8 SDR、现有色彩/范围设置、尺寸裁剪与 CPU 回退；输入仍携带正确可见尺寸和 D3D11 array slice。
- 保留共享纹理的租约、keyed mutex、零超时策略和录制 Feed；设备、上下文、转换器、线程的销毁顺序必须明确。
- 不新建与 QRhi 节点竞争的帧消费路径，不将预览转换变成重复 CPU 回读。
- 不恢复 GUI 副本模型、播放状态副本或新的全局服务；公开 QML 接口和配置键保持兼容。

### 验收

- 先建立设备、线程和资源所有权清单，分批提取后核对旧实现是否真正移除，没有留下两套转换入口。
- 继续验证 BGRA、NV12/P010 可见区域与 slice、尺寸变化、转换失败、CPU 回退、取消和资源释放；软件设备不支持的 VideoProcessor 路径要明确列为真实设备验收，不能将跳过记为通过。
- 每个拆分批次构建 Release、执行相关定向检查，最终执行完整 checks；真实录制分辨率、画质与长时间吞吐由用户验收。
