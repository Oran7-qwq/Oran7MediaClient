## 本次发现的问题

### A-01：防抖保存尚未完成时关闭窗口，末次工作台设置没有补交（已修复）

优先级：P2。影响设置持久化，不影响已验证的媒体文件收尾。

- 工作台音频与推流参数使用两秒防抖；`Oran7RecordingWorkspace.qml` 的销毁处理仅撤销音频监测意图，没有补交这两类草稿。
- `main.qml` 的关闭处理进入 `Qt.quit()`；Client 的退出保存没有读取工作台草稿。因此最终配置保存仍使用旧快照。
- 隔离复现：将系统音量从 100 改为 23、直播码率从 6000 改为 8000，在两秒内立即关闭窗口。保存快照仍为 100 / 6000。手动调用同一组件的 `saveLive()` 后，两项都能保存，排除非法参数造成拒绝的情况。
- 工具输出：`audio_flushed=0 live_flushed=0 before_audio=100 after_audio=100 before_bitrate=6000 after_bitrate=6000`。
- 建议：在采集控制器冻结前统一补交工作台有效草稿；非法或保存失败需明确处理，不延迟正在关闭的输出；补充真实关闭边界的持久化回归。

2026-11-17 修复：工作台监听宿主窗口 Closing，立即独立补交音频、推流和实际编辑过的本地输出草稿；控制器 shutdown 在冻结接口前同步发出 settingsFlushRequested，覆盖没有窗口 Closing 的退出入口，并阻止补交过程重入 shutdown。已有成功提交不重复保存；无效/失败参数保留最后成功值并记日志，不阻止关闭。采集来源仍以首帧确认后落盘，退出补交不触发预览重建、采集应用或自动录制。page_checks 新增即时关闭、控制器补交、重复提交及失败重试断言；recovery_checks 验证先保存再冻结和双输出退出顺序。

### A-02：窄窗口下底部音频工具区被压至零宽（UI 首版已修复）

优先级：P2。影响控制可达性。

- `Oran7RecordingToolbar.qml` 的 `recordingAudioTools` 设置 `Layout.minimumWidth: 0`；三枚启停按钮占据固定空间。
- 在实际工作台 QML、850×680 的隔离窗口中，实测音频工具区宽度为 `0.00`，系统声、麦克风及电平区完全不可见。内部虽有横向滚动，零宽视口无法供用户操作。
- 原 `page_checks` 检查了窄窗口侧栏布局和启停按钮可达，没有要求音频工具区保持非零可用宽度，故原检查仍通过。
- 建议：给音频区保留最小可操作宽度，并提高中栏/整行最小宽度，延续整行横向滚动，不把工具栏换到预览下面或增加多行高度。

2026-11-17 UI 改版：中栏底部为独立混音区，录制/推流按钮移到右侧固定输出卡片。中栏最小宽度 480、音频视口最小宽度 446，两个声源模块各至少 220；整行最小宽度 990，不足时横向滚动。检查新增窄窗口视口宽度下限、两声源可达及启停状态下预览几何稳定断言。混音区含小标题和单独状态行，固定 110 高，不随运行状态伸缩。

## 仍需用户真实设备验收

1. 实际显示器切换、分辨率变化、不同 GPU/缩放比例下的预览恢复，核对显示器名称与画面一致。
2. 系统声、默认麦克风、权限关闭/设备不可用的提示；录制文件与手机观众端分别验证增益、静音、无白噪声和音画同步。
3. 录制 240fps 与 RTMP 1080p60/1440p60 并行，观察 GPU 编码会话、CPU、实际帧率、队列和丢弃；离线软件测试不替代该吞吐验收。
4. 两种启动顺序、分别停止、推流断网/失败重试，以及两路同时运行时关闭主窗口；检查文件可打开、进程最终退出、麦克风与采集资源释放。
5. 连续 30～60 分钟实际平台播放，观察延迟、音画漂移和内存是否持续增长；本次未做长时间或真实公网测试。
