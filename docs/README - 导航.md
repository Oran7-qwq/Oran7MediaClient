## 阅读顺序（新人接手）

1. [[ARCHITECTURE - 架构]] —— 程序由什么组成、怎么启动、依赖方向。
2. [[RUNTIME_STATE - 运行时状态]] —— 每个"事实"存在哪、谁是权威、怎么落盘。
3. [[ASYNC - 异步与线程]] —— 哪些代码在哪个线程、跨线程规则。
4. [[DATAFLOW - 数据路由]] —— 一次点击从 QML 到内核再回来。
5. [[MODULES - 模块]] —— 模块地图 + 全量 QML 注册清单。
6. 按需读各模块详情（下表）。
7. [[PATTERNS - 设计模式与约定]] —— 新增代码照哪个模板写。
8. [[REFACTOR - 重构路线]] —— 已知问题、优先级与迁移顺序。

## 写作规范

1. 全仓库注释与用户可见文本用**中文**，文档同样用中文。
2. 每个 `.md` 顶部带 frontmatter，至少 `status`、`updated`。
3. 文档之间用 Obsidian 双链 `[[文件名]]`，不用完整路径。
4. 指向源码用相对路径 + 行号，例如 `src/cpp/Oran7MediaClient/Oran7MediaClient.cpp:95`。
5. 待办用 `<!-- TODO: ... -->` 标记，方便全局搜索。
6. 历史决策写进 [[ADR/README]]，功能文档用双链指过去，不重复长篇论证。
7. 新增/改动 `qmlRegister*` 或 `Oran7UI.Impl` 导出类型 → 更新 [[MODULES - 模块]] 的全量清单 + 对应模块文档的「对外接口」。
8. 发现"同一事实存在多处"时，先更新 [[RUNTIME_STATE - 运行时状态]] 的所有权表，再改代码。
